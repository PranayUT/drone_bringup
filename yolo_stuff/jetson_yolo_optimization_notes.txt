TensorRT export (one-time)
- export LD_PRELOAD=/usr/lib/aarch64-linux-gnu/libgomp.so.1
- yolo export model=best-v1.pt format=engine half=True imgsz=640 end2end=False workspace=4
- Pip failures for onnxruntime-gpu and tensorrt-cu11 on Jetson are expected; use JetPack TRT.

Power / clocks
- sudo nvpmodel -m 0 && sudo jetson_clocks per boot for max performance

Flying: keep preview + comfortable resolution + solid detection
- YOLO still resizes to --imgsz (default 640) internally; 1080p preview helps the pilot more than the detector. Prefer --cam-fps 30 or 35 (smooth enough to fly, less capture/encode load than 60). Pair with 1280x720 if you want more CPU headroom, or keep 1920x1080 with lower fps.
- Keep TensorRT .engine + --task segment + LD_PRELOAD for inference.
- bench_best_v1.py: --infer-every N (camera only) runs YOLO every N frames; preview redraws the last masks/boxes onto each new frame (no flashing). Detections still refresh only every N frames, so fast motion can lag slightly until the next infer.
- Example: export LD_PRELOAD=/usr/lib/aarch64-linux-gnu/libgomp.so.1 && python3 ~/bench_best_v1.py --source camera --weights ~/best-v1.engine --task segment --preview --cam-width 1280 --cam-height 720 --cam-fps 30 --imgsz 640 --infer-every 2

start_mission.sh + YOLO / CSI camera
- Default: script restarts nvargus-daemon then launches ROS bringup — any other nvarguscamerasrc client must be stopped first or it will break.
- Order: run ./start_mission.sh first; after bringup is healthy, start bench/YOLO only if CSI is not already owned by ROS (jetson_csi_cam is currently commented out in bringup.launch — recheck before flying).
- To avoid bouncing nvargus when you know the daemon is fine: SKIP_NVARGUS_RESTART=1 ./start_mission.sh …
- Optional: NVARGUS_SETTLE_SEC=5 to wait longer after restart (default 3 in script).
